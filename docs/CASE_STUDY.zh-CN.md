## 现象

用户在 Claude Desktop 第三方 Code 环境经自建网关使用 DeepSeek。历史记录标注客户端 cc 2.1.286；**不能据此推广到所有 Claude Code CLI / Desktop 版本或默认配置**。

| 历史报告指标 | 数值与范围 |
| --- | --- |
| 修复前总体印象 | 命中率约 2–6% |
| 历史请求样本 | 3,541 请求，逐请求命中率中位数 4.0% |
| 反复出现的 cache_read 平台值 | 8,192–8,320 tokens |
| 修复后 system 指纹 | 16 发保持一致 |
| 修复摘要的前后值 | 4.6% → 92.7% |
| 同一摘要列出的 hit / miss | 847,232 / 67,386 |

**数值校核：** `847232 / (847232 + 67386) = 92.6323%`，保留一位应为 **92.6%**，与摘要所写 92.7% 不完全一致。缺少可公开的原始逐请求账本，无法解释差异；本项目明确保留它。4.0% 是逐请求中位数，与后验 token 加权率也不是同一统计口径。前后窗口是否严格等量没有公开证据，不能推出精确节省倍数或因果效应大小。

## 排查顺序：先缩小问题，再改请求

1. **供应商缓存是否可用？** 历史记录中的固定请求直连探针可以高比例命中，说明缓存并非在整个测试期间完全不可用。
2. **是否网关传输本身破坏了前缀？** 记录中 9 种受控形态经过网关均超过 99% 命中，包括长输入。它缩小了怀疑范围，不代表网关永无其他问题。
3. **是否只是间隔太久？** 记录中相邻约 2 秒的实际请求仍失效，所以简单的“隔了五分钟过期”不能解释该样本。
4. **是否历史消息改写？** 指纹对比显示所查历史 messages 稳定，继续检查更靠前的 system。
5. **定位首个变化。** system 长度和内容持续变化，发现 billing 版本尾号与追加的 hook/token 上下文。

以上来自内部记录 `:11–19`。历史探针的账号、并发、预热等完整条件未公开，因此本项目把它们作为排查过程报告，而非供应商性能基准。

## 当时到底变化了什么

两类变化同时存在：

- `x-anthropic-billing-header` 文本行里的 `cc_version` 尾号在请求间变化。
- `UserPromptSubmit hook additional context` 与 `<total_tokens>` 内容不断追加或更新。

system 处于请求前部。变化可能让后续请求无法复用先前已经落盘的长前缀；并不意味着服务器完全不能命中更短的公共部分。JSON 字节差异是本地诊断线索，**不是对供应商内部 token 序列、缓存键或缓存块布局的直接观察**。

DeepSeek 当前官方文档说明按已落盘前缀匹配、提供 hit/miss usage 且不保证每次命中。不要从当年的平台值推导永久块大小、固定 TTL 或所有模型通用规则。[官方说明，2026-10-10 查阅](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)

## 修复选择与公开版差异

历史网关在转发前删除纯计数器块及包含 hook 标识的块，并固定版本号、混合文本内计数值。该环境的交接记录报告命中明显改善。

公开版没有无条件照搬：

| 历史实现 | 公开版 |
| --- | --- |
| 转发路径自动启用 | 全部规则默认关闭，逐项选择 |
| 文本中匹配任意 `cc_version` | 仅匹配 billing-header 行 |
| 空文本可能随纯计数器规则一起删除 | 必须确实含计数器标签，保留原有空文本 |
| 普通短哈希 | 每实例随机密钥的完整 HMAC-SHA256 |
| 打印 system 尾部和差异窗口 | 不返回正文，只返回指纹、长度、差异位置 |

历史文档曾将日志描述为“无正文”，但复核源码发现其尾部与差异窗口包含正文片段。公开版纠正了这一点；本次没有修改原运行服务。

Hook 文本可能含安全策略、审批要求或实际用户指令；计数器可能影响预算规划。**丢弃它们属于语义变更，不能默认视作无害元数据。** 最优先从注入源消除无意义的变化。网关改写只用于已审查、可回滚的路径。

## 怎么验收

- 同一会话、同一路由中比较 system、tools、历史 messages；不要把多个用户或并行子代理串成一条时间线。
- 固定模型、端点、账号、选项与合成前缀，先观察原始请求，再单独启用候选规则。
- 本地结构测试通过后，独立记录供应商 hit/miss、总输入、未知 usage 数和实际成本。切勿用延迟降低代替 usage 证据。
- 加权命中率 = `sum(hit) / (sum(hit) + sum(miss))`；未知字段保持未知。不能直接平均每请求百分比。
- 验证多轮行为、工具调用、预算与权限提示。真实任务是否正确仍需单独验收。
- 出现语义损失或错误时关闭对应选项；回滚后重启调用方是否必要由接入方式决定。
